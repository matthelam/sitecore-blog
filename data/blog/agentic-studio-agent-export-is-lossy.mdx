**In short:** Agentic Studio's agent export quietly drops Agent Type and Tags. Knowing that is the workaround: note both before you export, and put them back after every import.

This is a short post about a small quirk I found whilst working on Agents in Agentic Studio. It's easy to overlook, because nothing errors. When [exporting an agent](https://doc.sitecore.com/sai/en/users/sitecoreai/working-with-agentic-studio/understanding-agents/export-or-import-an-agent.html) there are 2 fields that get dropped or cannot be exported, even when you add them manually:

1. **Agent Type**
2. **Tags**

Set them in the editor, export the agent, import it again, and both come back empty.

## What the export file shows

We tested this deliberately back in July. Set both fields, re-exported, and the file gained no keys at all, nothing resembling a type or a tag anywhere in it.

Then it got murkier. An export I took this month has tags sitting in it at the top level:

```json
"tags": ["SEO", "AEO", "Metadata"]
```

So either the platform changed between July and August, or our original test was narrower than we thought. I have not managed to separate those two yet.

## Knowing is the workaround

Before you export, note the agent's Agent Type and Tags. Then after an import:

1. Import the agent. You need a Builder License to create an agent by importing a JSON file, which is covered in [Assign Yourself a Builder License First](/blog/agentic-studio-builder-license).
2. Open the agent and check Agent Type and Tags.
3. Put both back from your notes.
4. If the agent uses a widget, re-point it as well. Widgets have no export, and the agent's own export carries a `widgetTemplateId` that refers to nothing in the target tenant (see [Widgets Do Not Export](/blog/agentic-studio-widgets-do-not-export)).

## Status

I logged a support ticket with Sitecore about this. It was closed with a general response suggesting it won't be fixed, or that the behaviour is intentional.

Nothing too alarming as I see it, but it's something to be aware of as you test out and migrate your agents around instances.

Note them before you export. Put them back after you import.
