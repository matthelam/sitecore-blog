**In short:** after you export an agent in Agentic Studio and import it again, Agent Type and Tags come back empty, so re-apply both by hand after every import. Whether the export file carries tags at all changed between my July test and an August export, and I haven't worked out why.

This is a short post about a small quirk I found whilst working on Agents in Agentic Studio. When [exporting an agent](https://doc.sitecore.com/sai/en/users/sitecoreai/working-with-agentic-studio/understanding-agents/export-or-import-an-agent.html) there are 2 fields that get dropped or cannot be exported, even when you add them manually:

1. **Agent Type**
2. **Tags**

Set them in the editor, export the agent, import it again, and both come back empty. You re-apply them by hand every time.

## What the export file shows

We tested this deliberately back in July. Set both fields, re-exported, and the file gained no keys at all — nothing resembling a type or a tag anywhere in it.

Then it got murkier. An export I took this month has tags sitting in it at the top level:

```json
"tags": ["SEO", "AEO", "Metadata"]
```

So either the platform changed between July and August, or our original test was narrower than we thought. I have not managed to separate those two yet.

## What to do after an import

What hasn't changed is the practical bit: after an import, check Agent Type and Tags and re-apply them.

1. Import the agent. You need a Builder License to create an agent by importing a JSON file, which is covered in [Assign Yourself a Builder License First](/blog/agentic-studio-builder-license).
2. Open the agent and check Agent Type and Tags.
3. Re-apply both by hand.
4. If the agent uses a widget, re-point it as well. Widgets have no export, and the agent's own export carries a `widgetTemplateId` that refers to nothing in the target tenant (see [Widgets Do Not Export](/blog/agentic-studio-widgets-do-not-export)).

## Status

I have logged a support ticket with Sitecore about this and will update this post once I hear back on the outcome.

Nothing too alarming right now as I see it, but it's more just something to be aware of as you test out and migrate your agents around instances.

It is one gap on the way from a dev instance to Production. Some artefacts move cleanly, some move partially like this, and at least one does not move at all.
