So I built something for that job. **seo-jev-analyzer uses Jev, a decision model rather than a chatbot, to score whether a page answers the question people search for, consistently enough to test a title or description before you publish.**

## Why I built it

Tuning content for search was a slow round trip. Change a title, publish, wait, guess. I wanted that loop in seconds.

Google is clear about where the effort should go. Its [SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) says creating content people find compelling and useful "will likely influence your website's presence in search results more than any of the other suggestions in this guide". It also says: "Think about the words that a user might search for to find a piece of your content."

Tools like is-agentic have already solved the technical side. What I couldn't find was something that helps an author check whether the page they just wrote has a clear purpose, and whether that purpose lines up with the searches they expect it to answer.

## What it scores

For each page you write two things: an **intent statement**, the question the page must answer, and **ten expected search terms**. Jev then rates two things on a 0 to 1 scale: how central each term is to the page, and how well the page answers the intent (the **intent fit**).

**Score = (sum of the ten term ratings) × intent fit**, from 0 to 10.

It produces two scores. The **metadata** score reads only the title, description, Open Graph tags and JSON-LD: what a search result shows. The **whole page** score adds the body text.

Multiplying by intent fit is the important part, because it discounts keyword stuffing. The tool's guide shows it with three versions of the same page's metadata:

| Metadata                                         | Term sum | Intent fit | Score |
| ------------------------------------------------ | -------- | ---------- | ----- |
| A casual title, no description                   | 0.68     | 0.006      | 0.00  |
| A title and description that answer the question | 3.40     | 0.99       | 3.37  |
| A list of the ten terms                          | 5.44     | 0.37       | 1.99  |

The list of terms carries the most keywords and still loses to the version that answers the question.

## Why Jev

Most AI you meet generates text. Ask a chat model to rate a page and you get prose back, with a number somewhere in it.

[Jev](https://docs.typesafe.ai) is TypeSafe's decision model. You give it text and a typed question, and it returns a probability for every possible answer instead of writing one. That's the niche it fills in AI: judgement, not generation.

For seo-jev, every rating is a question with five levels, from "not mentioned" to "the page's central subject". The rating is the probability-weighted level. Jev is also cheap: $0.042 per million input tokens, with output free. That makes it practical to score a draft several times while you edit.

## Can you trust a number from a model?

It's the first question to ask of any new tool, so I measured it. The [consistency report](https://github.com/matthelam/seo-jev-analyzer/tree/main/docs/evidence/jev-consistency-2026-10-14) froze the text of 10 public pages, so only Jev could vary, and scored each page 100 times on both scores: 6,000 Jev requests.

- The largest standard deviation of any score was **0.097** on the 0 to 10 scale.
- **99.7%** of single runs landed within ±0.19 of their 100-run mean.
- **17 of 20** metadata edits were detectable from one run before and one run after.

That ±0.19 is the tool's noise floor. A change smaller than it counts as level, not as a win.

The report is honest about its limits: one Jev version, one day, ten English pages. In its own words, it "measures consistency, not correctness".

## Why it helps tuning

The tool's `test_revision` scores an edit against the live page before anything is published. That's the round trip I wanted.

Part two of my [Azure Entra ID SSO series](/blog/02-SSO-Entra-ID-Setup) shows what that buys. Its whole page scored well, but its metadata didn't say what the page does:

**The score didn't just say the metadata was weak. It said where: the description never answered the question.** The metadata now carries 77% of what the whole page scores, up from 38%.

## Beside the traditional tools

I run both. is-agentic tells me whether machines can read the site. seo-jev tells me whether a page answers the question it's meant to. Neither replaces the other.

One caution from my own tuning: the ten terms have to come from researching the question, not from the page. When I drafted terms from the post itself, the post scored higher (metadata 4.12, against 3.11 for terms researched from the intent alone). That's the page being marked against what it already says. The lower number was the honest one.

## What isn't right yet

The ceiling. Scores run from 0 to 10, but a page is never going to reach 10, and the theoretical ceiling isn't clear. So what counts as success isn't clear either.

For now I use the whole page score as the practical ceiling for the metadata, which is where that 77% comes from. It's a working measure, not a settled one.

## Run your own

The hosted instance is mine and stays private. It runs on my own Jev account, which isn't for commercial use. It's cheap, but I'm not ready for it to scale if it gets popular.

The code is public. [seo-jev-analyzer](https://github.com/matthelam/seo-jev-analyzer) is MIT licensed and runs as a web app, an MCP server with eight tools (including `score_page` and `test_revision`) and an HTTP API. You bring your own TypeSafe key from the [TypeSafe console](https://console.typesafe.ai/keys) and set an access password. The app refuses to run in production without one, because an open deployment spends your Jev credits.

The tuning loop I used on this blog is packaged as a Claude Code skill: [seo-tuning-skill](https://github.com/matthelam/seo-tuning-skill).

```text
/plugin marketplace add matthelam/seo-tuning-skill
/plugin install seo-tuning@seo-tuning-skill
```

Write the question your page answers before you write the title. Then let the score tell you whether the title says it.
